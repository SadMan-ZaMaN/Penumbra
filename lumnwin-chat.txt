Yes, and it's a very doable project. One correction first: Lumn reacts
to the beat of whatever's playing and takes its colors from the album
art. It doesn't follow lyrics. On Mac it draws a glowing rim around the
screen edges.

What you'd build on Windows:

1. Glow overlay. Make a fullscreen, transparent, always-on-top window
   that clicks pass through. Draw the gradient glow along the edges.
2. Audio capture. Use WASAPI loopback to grab system audio (what's
   playing, not your mic). Run an FFT on it and track bass energy to
   detect beats, then drive the glow's brightness and size with that.
3. Album colors. Windows exposes the currently playing media (Spotify,
   browsers, and so on) through the
   GlobalSystemMediaTransportControlsSessionManager API. Grab the
   thumbnail, pull out 2-3 dominant colors, and use them for the
   gradient.
4. Tray app. Add a system tray menu for color, thickness, glow
   strength, and on/off.

Recommended stack: C# + WPF + NAudio. All four pieces are native and
well documented there. Python also works (PyQt overlay + pyaudiowpatch +
winsdk), but performance is worse.

Optional lyrics extra: You can get synced lyrics from the free LRCLIB
API, match them to the playback position from the same media API, and
pulse or change color on each line.

Effort: A basic beat-reactive glow takes a weekend. Making it polished
and lightweight takes a couple of weeks.

Since you know Java, pick up C#. It's nearly the same language, and
it's the easiest way into the Windows APIs this needs. Python works for
a prototype, and C++ works if you want it lean, but expect more
boilerplate.

Signal processing (just the basics):
- Sampling: audio is a stream of numbers (e.g. 48,000 per second). You
  process it in small chunks of about 1024 samples.
- FFT: converts a chunk into frequencies. Bass sits roughly at
  20-150 Hz, which is where beats live.
- Energy / RMS: how loud a frequency band is right now.
- Beat detection: a beat is when current bass energy jumps above its
  recent average (e.g. the last ~1 second).
- Smoothing: use attack/decay or a moving average so the glow doesn't
  flicker.

You don't need deep DSP theory. A couple of YouTube videos on FFT plus
one "simple beat detection" article covers it.

Windows / coding:
- WASAPI loopback: capturing system audio. NAudio in C# does it in a
  few lines.
- Transparent overlay windows: layered, topmost, click-through windows
  in WPF or Win32.
- SMTC (media session API): gets the now-playing song and its album
  art.
- Color extraction: k-means or simple histogram bucketing to find
  dominant colors.
- Threads: audio runs on one thread and rendering on another, so you
  need to pass data between them safely.
- Basic graphics: drawing gradients and blur/glow effects.

Suggested order:
1. In Python, capture system audio and print bass energy, so you see
   the signal stuff working fast.
2. In C#, build the transparent edge overlay.
3. Connect the two so the glow reacts to the audio.
4. Add album-art colors, then a tray menu.

No, C# isn't required. Each of your languages can do it:

- C++: fully capable, since all the Windows APIs are native to it. The
  catch is more boilerplate (COM, Win32 window code) and slower
  iteration.
- Python: fine for the whole thing if you accept somewhat higher CPU
  usage. Use pyaudiowpatch for loopback audio, numpy for the FFT,
  winsdk for now-playing and album art, and PyQt or PySide for the
  overlay.
- Java: the weakest fit. Getting at system audio loopback and the
  Windows media APIs needs native bridges, which gets messy.

Is C# easy? For you, yes, very. It's about 90% Java syntax (classes,
generics, interfaces), and the differences are small: properties,
var, LINQ, async/await. You'd be productive in a few days. Its main
advantage here is that NAudio and WPF make audio capture and the
overlay window take a few dozen lines instead of hundreds.

My pick for you: start in Python, since you already know it and can
test ideas fast. If it feels heavy or you want a polished app, port it
to C# later, which is a quick switch coming from Java.

LumnWin is in LumnWin.zip: a Python engine and a C# overlay that work
together like Lumn. It hasn't run on Windows yet, so expect a few small
fixes on first launch.

How it's split:
- Python engine (engine/): captures system audio and detects beats
  from bass energy. It also gets the now-playing song and album art
  from Windows, picks two colors from the art, and fetches synced
  lyrics from LRCLIB. It sends all of this about 60 times a second to
  the overlay.
- C# overlay (overlay/): four thin, click-through windows glow along
  the screen edges. The colors slowly orbit around the screen and
  pulse on each beat. There's also an optional lyric line above the
  taskbar and a tray menu for mode, thickness, glow, brightness,
  colors, lyrics and start-with-Windows.

To run it: install Python and the .NET 8 SDK, then double-click
setup.bat once and run.bat after that. "debug.bat --demo" shows the
glow with a fake beat, so you don't need music to test it.

What I could and couldn't test here:
- Tested: I ran the signal processing on synthetic music. It found 25
  beats on a 128 BPM track (about 24 expected) and estimated the tempo
  at 127.8 BPM. I also tested the album-color picking, lyric parsing,
  the 60-per-second data stream, and that the engine quits when the
  overlay closes.
- Not compiled: my sandbox couldn't download the Windows UI packages,
  so the C# hasn't been compiled. I checked it for syntax errors and
  reviewed it by hand.
- Not tested at all: audio capture, the now-playing info and the
  lyrics download only work on a real Windows machine with internet.
  The lyrics API's parameters match LRCLIB's documented interface.

The README lists the few numbers that control the feel, like beat
sensitivity and pulse size, so you can tune it while learning how it
works. dsp.py is the signal-processing part worth reading first.

Sources:
- lrclibapi docs (LRCLIB endpoints):
  https://lrclibapi.readthedocs.io/en/stable/_modules/lrclib/api.html
- Lumn: https://www.trylumn.xyz/

Here are some ideas, grouped by feel:

Light-themed
- Halo: a glowing ring around your screen.
- Penumbra: the soft edge of a shadow, which is exactly what the glow
  looks like.
- Corona: the glowing ring around an eclipse.
- Lumina: soft and elegant.

Music-themed
- Pulse: simple, and says it reacts to the beat.
- Afterglow: the light that lingers after the music.
- Bassline: the glow literally follows the bass.
- Encore

Short and brandable
- Glowr
- Rimlit: lit from the rim.
- Edgy: playful, since it lives on your screen edges.
- Aura

My pick is Penumbra. It's distinctive, describes the effect
accurately, and doesn't sound like another RGB app. If you want
something shorter, go with Halo or Rimlit.

Before you commit, search the name on GitHub and the Microsoft Store to
check it isn't taken. Names like Halo, Aura and Pulse are probably
already used by other apps.
